# SixSentences v0.2.0-alpha.4

This evaluation prerelease corrects the order of release publication and updates
the API's runtime PDF parser from pypdf 6.18.1 to 6.19.0 for security fixes.
Application logic, database migrations and other canonical third-party dependency
versions are unchanged from alpha.3. Component metadata advances together to a
new immutable version; no existing release, image or source note is replaced.

## PDF dependency security update

pypdf 6.19.0 fixes denial-of-service issues in alphabetical page labels,
form-field flattening and dictionary-based embedded-file access. The current
API does not call these specific features; no reachable exploit path was
demonstrated in this review. It does process untrusted PDFs, so the affected
runtime package is updated rather than treated as development-only.
See [the dependency triage](https://github.com/SixSentences/sixsentences/blob/v0.2.0-alpha.4/docs/DEPENDENCY-TRIAGE-2026-10-01.md) for the three
upstream advisories, scoped lockfile changes and validation boundaries.

## Why a new version

Alpha.3's source release and attested Python-engine artifacts were published on
2026-10-01 and remain valid. Its image builds, scans, isolated startup/upgrade/
restore drill and provenance validation also passed. The final attempt to attach
image evidence failed with HTTP 422 because the GitHub release was already
immutable. Those image-evidence assets are absent from the alpha.3 release;
successful workflow checks are not a substitute for attached receipts.

GitHub's [immutable-release guidance](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases)
requires all assets to be attached while the release is still a draft. Alpha.4
addresses [#185](https://github.com/SixSentences/sixsentences/issues/185) by making
publication the last step of one orchestrated workflow, without disabling that
protection or retrying uploads against an immutable release.

## Publication contract

- All source, build, test, attestation, self-hosting, security and preview gates
  must pass before the protected reusable image job runs.
- The exact registry digests must pass scans, the provider-free runtime drill
  and strict metadata validation. The image job then exports ten sanitized
  evidence files to the same workflow run, not to an already-published release.
- The protected final publisher verifies this run's engine and image evidence,
  checks the GIF-only draft, and uploads fourteen files without overwriting.
  It then downloads and validates the exact fifteen-file inventory and bytes.
  Only a successful final check allows the draft to become a public prerelease.

The uploaded assets are the unchanged reviewed GIF, Python wheel, sdist,
CycloneDX SBOM and `SHA256SUMS`, plus `IMAGE_DIGESTS`, `images.json`, two image
SBOMs, two provenance exports, two OCI identity records, `runtime-rehearsal.json`
and `IMAGE_SHA256SUMS`. Generated source archives and release notes are not extra
uploaded assets. Missing or unexpected files fail closed; image tags and release
assets are never clobbered. Partial failures remain available for inspection.

These describe required gates, not a claim that preparation alone has passed
them. Alpha.4 is complete only when its own workflow, remote artifact checks and
maintainer verification succeed. Prior versions' receipts are not reused as
proof for new digests.

## Install and recovery boundaries

```console
git clone --branch v0.2.0-alpha.4 --depth 1 https://github.com/SixSentences/sixsentences.git
cd sixsentences
bash deploy/community/init-env.sh --local
docker compose --env-file .env.selfhost up --build --detach --wait
```

Prebuilt images cover Linux amd64 and the explicit localhost web origin only;
TLS-origin web images remain operator-built. Use the verified `@sha256:`
references from `IMAGE_DIGESTS` and check both checksum files before deployment.
Read `deploy/community/README.md` and `deploy/community/BACKUP-RESTORE.md` first.
Back up database/files and retain the newer independently held authenticated
erasure journal before changing releases.

The required upgrade/rollback pair remains the pinned alpha.1 API and the
alpha.4 candidate, using the hash-bound original-schema compatibility bootstrap
and a real synthetic legacy corpus. It is not a dedicated alpha.3-to-alpha.4
upgrade test, proof of an unchanged alpha.1 installer, a safe schema downgrade,
or a guarantee that post-snapshot writes survive rollback. Fresh candidate
startup without a corpus and newer-journal erasure replay remain mandatory.

Provider/privacy gates and the community/hosted boundary are unchanged. No new
media, billing, production configuration or data, provider credentials, or
signed/notarized native binaries are included. The macOS Companion remains
source-only. This is alpha software; see `docs/RELEASING.md`, `LICENSE`,
`THIRD_PARTY_NOTICES.md` and `TRADEMARKS.md` for the full boundaries.
