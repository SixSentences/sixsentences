# SixSentences v0.2.0-alpha.2

This evaluation prerelease strengthens the complete community research
workspace: engine, API, worker, PostgreSQL migrations, web client and self-host
tooling, plus browser-extension and macOS Companion source. Hosted billing,
production infrastructure, credentials, customer data and the marketing site
remain outside the source distribution.

## Highlights

- Personal, creator-private pinboards with persisted resizing, responsive
  editing, drag/keyboard positioning and a recover-obscured-notes action.
- Next.js 16.3.8, a corrected restore-selector syntax error and regression tests.
- Required provider-free Compose startup, upgrade from the published alpha.1
  API digest, synthetic note/file backup-and-restore checks and post-backup
  account-erasure replay that rejects resurrected records or files.
- A separately approved container publication workflow checks signed release
  ancestry, OCI revision/version, SBOM/provenance and exact published image
  digests with a runtime rehearsal before attaching checksum receipts.
- Broader command-line output controls and community provider catalogs, with
  deployment-specific privacy and budget gates preserved.
- The owner-supplied thesis-film preview already used in the README, now bound
  to this release by its checked-in checksum under `sixsentences-overview.gif`.

## Install and upgrade

```console
git clone --branch v0.2.0-alpha.2 --depth 1 https://github.com/SixSentences/sixsentences.git
cd sixsentences
bash deploy/community/init-env.sh --local
docker compose --env-file .env.selfhost up --build --detach --wait
```

Read `deploy/community/README.md` and `BACKUP-RESTORE.md` before accepting data.
Keep registration and external processing disabled until operator mail,
participant notices, provider terms and privacy controls are configured.
Existing deployments must back up their database/files and independently held
erasure journal before migrating. Migration `20260928_0003` adds pinboards;
size values are forward-compatible with clients that omit them, but restoring
an older server can discard size metadata on its next write. No automatic
rollback or downgrade without data loss is promised.

## Artifacts and limits

The release workflow validates the tagged source and publishes attested Python
engine distributions. Container publication is a separate protected workflow:
do not assume images are available until `IMAGE_DIGESTS`, SBOM/provenance,
OCI identity records and `runtime-rehearsal.json` are attached. Only Linux amd64
and the explicit localhost web origin are covered; TLS-origin web images must
be operator-built. Source-bound receipts are not independent security audits
or promises of byte-identical rebuilds.

The keyless runtime drill tests API/Compose behavior and synthetic notes/files.
It does not replace browser accessibility tests, research-quality evaluations,
operator disaster-recovery practice or deployment-specific legal review.
Successful runtime evidence must include authenticated erasure-journal replay;
a prior-version rollback drill remains follow-up work in #29. Do not interpret
same-version restore success as proof of safe downgrade.
The native Companion remains source-only, without signed/notarized binaries,
an appcast or a store identity.

This remains alpha software with potentially changing APIs and migrations.
Source licensing and protected marks are documented in `LICENSE`,
`THIRD_PARTY_NOTICES.md` and `TRADEMARKS.md`.
